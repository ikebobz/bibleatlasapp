# Reliable iPhone install experience

## What I found in the current app

- The manifest at `/manifest.webmanifest` is valid and complete (name, short_name, start_url `/`, scope, `display: standalone`, 192/512 any + maskable icons, theme and background colours). No Lovable branding.
- `apple-touch-icon`, `apple-mobile-web-app-capable`, `apple-mobile-web-app-title`, `theme-color` and the manifest link are all present in the site head.
- The service worker is generated by the standard PWA plugin with auto-update, registration is guarded so it never runs in preview/iframe/dev.

So the app *is* installable on iOS. The failure is in the prompt UI, not in the PWA plumbing:

1. The banner shows a **non-interactive grey pill** reading "Share → Add to Home Screen". It looks like a button but nothing happens on tap — this matches the "button doesn't respond" reports exactly.
2. It appears after a fixed 1.8s on the very first page view, before the user cares, and a single dismissal hides it forever.
3. There is no picture of the Safari Share icon, no step list, and no page to fall back to. Users who miss the tiny hint have nowhere to go.
4. It is skipped entirely inside in-app browsers (Instagram, Facebook, Gmail) with no guidance to reopen in Safari — a very common way people first open a shared verse link.

## What I'll build

**1. Platform detection helper** — one shared module that reports: iPhone / iPad / iOS Safari / iOS in-app browser / Android Chrome / desktop / already installed, using both `display-mode: standalone` and the iOS `navigator.standalone` flag.

**2. Real install guide (the fix)** — a tappable "Show me how" button opens a branded sheet with the Bible Atlas icon and three illustrated steps: tap Share, scroll to "Add to Home Screen", tap "Add". Includes a drawn Safari share glyph so the user knows exactly what to look for and where it sits (bottom bar on iPhone, top bar on iPad).

**3. Rewritten install banner** — same brand styling, but now: real buttons, "Show me how" (iOS) or native Install (Android/desktop), "Not now" (returns later), and "Don't show again" (permanent). Shown at a natural moment instead of immediately: second visit, or after real reading activity, and never in standalone mode.

**4. In-app browser path** — inside Instagram/Facebook/etc. the banner instead says "Open in Safari to install", with copy-link and instructions, rather than staying silent.

**5. `/install` page** — a dedicated, indexable page with tabs for iPhone, iPad, Android and Desktop, auto-selecting the visitor's platform, plus a short FAQ ("I don't see Add to Home Screen", "the icon is missing", "how do I read offline"). Linked from the banner and the settings menu.

**6. iOS metadata polish** — add `viewport-fit=cover` and the Apple status-bar style so the installed app fills the screen correctly under the notch; keep every existing tag and icon.

**7. Analytics** — extend the existing event list with `install_prompt_opened`, `install_instructions_viewed`, `standalone_app_opened`, plus platform/browser labels. No personal data.

Untouched: manifest contents, service worker/offline behaviour, deep links, verse sharing, audio player, Android and desktop install.

## Testing

Playwright runs against emulated iPhone Safari, iPad, Android Chrome and desktop viewports to verify: the banner renders with a working "Show me how" button, the guide opens and shows all three steps, dismissal persists, standalone mode suppresses the banner, and `/install` renders each platform tab. Real device behaviour on iOS 17/18 hardware and the actual Add-to-Home-Screen result can't be automated — that needs a manual check on your iPhone after publishing.
